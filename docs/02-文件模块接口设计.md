# 阶段① 文件管理模块 —— 接口设计

> 约定：
> - 后端 context-path 为 `/api`，下表路径均省略前缀，实际访问如 `http://localhost:8080/api/v1/files`
> - 统一返回体 `R<T> = { code, message, data }`；分页返回 `PageResult<T> = { list, total, page, size }`
> - 除 `/auth/**` 外全部需要 JWT；`userId` 一律从 token 解析，**不接受前端传参**（防越权）
> - 文件实体不入库，库中仅元数据；下载/预览一律走 MinIO 预签名 URL（15 分钟有效）
> - 优先级：**P0** = 阶段①必做；**P1** = 阶段①内可后置

## 1. 认证 auth（4 个）

| 方法 | 路径 | 说明 | 关键参数 | 返回 data |
|---|---|---|---|---|
| POST | /v1/auth/register | 注册 | username, password, nickname? | userInfo |
| POST | /v1/auth/login | 登录 | username, password | accessToken, refreshToken, expiresIn, userInfo |
| POST | /v1/auth/refresh | 刷新令牌（轮换，旧的作废） | refreshToken | 新 accessToken + refreshToken |
| POST | /v1/auth/logout | 退出（撤销 refreshToken） | — | — |

安全约束：登录/注册接口限流（IP+用户名维度）；密码 BCrypt；refreshToken 存 Redis（`kb:token:refresh:{userId}`）可撤销。

## 2. 用户 user（3 个）

| 方法 | 路径 | 说明 | 返回 data |
|---|---|---|---|
| GET | /v1/users/me | 个人信息 + 配额使用情况 | userInfo, quota{quota, used, percentage} |
| PUT | /v1/users/me | 改昵称/邮箱/头像（白名单字段，防提权） | 最新 UserMeVO（user + quota） |
| PUT | /v1/users/me/password | 改密码 | oldPassword, newPassword；成功后强制重新登录 |

## 3. 文件夹 folder（4 个）

| 方法 | 路径 | 说明 | 关键参数 |
|---|---|---|---|
| GET | /v1/folders/tree | 整棵目录树（懒加载可后续优化） | — |
| POST | /v1/folders | 创建子文件夹 | name, parentId(null=根) |
| PUT | /v1/folders/{id} | 重命名 / 移动 | name?, parentId? |
| DELETE | /v1/folders/{id} | 删除文件夹 | 递归软删：子孙文件夹 + 其下所有文件全部进回收站 |

校验：不能把文件夹移动到自己的子孙目录下（防环）；同级重名拦截。

## 4. 上传 storage（P0 共 2 个，分片 3 个为 P1）

| 方法 | 路径 | 说明 | 关键参数 | 返回 data |
|---|---|---|---|---|
| POST | /v1/files/upload/hash-check | 秒传预检 | sha256, fileName, size, folderId? | `{instant, fileId}` —— instant=true 直接复用已有存储对象 |
| POST | /v1/files/upload | 上传文件 | multipart: file, folderId?, sha256?（前端算好带来，避免后端重读大文件） | fileInfo |
| POST | /v1/files/upload/init | P1 分片初始化 | fileName, size, sha256, partCount | uploadId |
| PUT | /v1/files/upload/{uploadId}/parts/{partNo} | P1 传分片 | multipart: part | 已传分片号列表 |
| POST | /v1/files/upload/{uploadId}/complete | P1 完成合并 | — | fileInfo |

上传校验链：扩展名白名单 + 魔数（magic number）复核 + 存储配额检查（超配额拒绝）+ Redis 锁防 sha256 并发重复入库。

## 5. 文件 file（P0 共 10 个）

| 方法 | 路径 | 说明 | 关键参数 |
|---|---|---|---|
| GET | /v1/files | 分页列表 | page, size, folderId?(0=根), categoryId?, tagId?, keyword?(文件名模糊), sortBy(name/size/createdAt), order |
| GET | /v1/files/search | 文件名全文搜索（MySQL ngram fulltext，走 ES 后升级为正文检索） | keyword, page, size, filters…；返回带高亮片段 |
| GET | /v1/files/{id} | 详情 | 返回元数据 + tags + category |
| PUT | /v1/files/{id} | 重命名 / 移动 / 改分类 | name?, folderId?, categoryId? |
| DELETE | /v1/files/{id} | 删除（软删 → 回收站） | — |
| PUT | /v1/files/{id}/star | 收藏 | — |
| DELETE | /v1/files/{id}/star | 取消收藏 | — |
| GET | /v1/files/starred | 收藏列表 | page, size |
| GET | /v1/files/recent | 最近访问 | limit(默认20)，按 file_access_log 去重聚合 |
| GET | /v1/files/{id}/download-url | 获取下载预签名URL（attachment），并记录 access_log(download) | — |
| GET | /v1/files/{id}/preview-url | 获取预览预签名URL（inline，按 mime type），记录 access_log(preview) | — |

说明：前端上传成功后本地已持有 sha256，秒传/普通上传共用 hash-check 预检；`GET /v1/files` 的 keyword 参数保留（简单 LIKE），`/search` 才走 fulltext + 高亮，避免语义混用。

## 6. 回收站 recycle（4 个）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /v1/recycle | 回收站分页列表（原名、原目录、删除时间、剩余保留天数） |
| PUT | /v1/recycle/{fileId}/restore | 恢复；原文件夹已被删则落根目录 |
| DELETE | /v1/recycle/{fileId} | 彻底删除（删 MinIO 对象 + file/file_tag/file_access_log 记录） |
| DELETE | /v1/recycle | 清空回收站 |

配套定时任务（非接口）：每天凌晨清理删除超过 30 天的记录。

## 7. 标签 tag（7 个）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /v1/tags | 标签列表（含每个标签的文件计数） |
| POST | /v1/tags | 创建 {name, color?}；同名去重 |
| PUT | /v1/tags/{id} | 重命名/改色（级联生效） |
| DELETE | /v1/tags/{id} | 删除标签并解除所有关联 |

| DELETE | /v1/files/{id}/tags/{tagId} | 移除文件的某标签 |

## 汇总

- **P0 共 34 个接口**：auth 4 + user 3 + folder 4 + 上传 2 + file 10 + recycle 4 + tag 7 + category 4 + 刷新等
- **P1 共 9 个**：分片上传 3、批量操作（batch move/delete/tags/zip下载 4）、stats 1
- 明确**不做**在阶段①：版本历史、分享链接、Office 转码预览（后续阶段）

## 主要错误码规划（已落地：common/result/ErrorCode）

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 用户名已存在 |
| 1002 | 用户名或密码错误 |
| 1003 | 账号已被禁用 |
| 1004 | 原密码不正确 |
| 1005 | 新密码不能与原密码相同 |
| 1010 | 未登录或登录已过期（前端触发刷新流程） |
| 1011 | 刷新令牌无效 |
| 1020 | 无权访问该资源 |
| 1030 | 请求过于频繁（限流） |
| 2001 | 文件不存在 |
| 2002 | 文件夹不存在 |
| 2003 | 同名冲突（同级文件夹、目标文件夹同名文件） |
| 2004 | 文件类型不允许（白名单/魔数校验失败） |
| 2005 | 不能将文件夹移动到其自身或子目录下 |
| 3001 | 存储配额不足 |
| 4001 | 请求参数不合法（校验失败统一映射） |
| 4002 | 上传文件过大 |
| 404 | 请求路径不存在 |
| 5000 | 服务器内部错误 |

## 建议实现顺序

common（R/异常/错误码）→ auth（JWT 过滤器链）→ user → folder → storage/upload → file → tag/category → recycle → 定时清理
