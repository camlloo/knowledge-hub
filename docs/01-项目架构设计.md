## 1. 项目定位与核心闭环

**AI Knowledge Hub = 文件系统 + 搜索系统 + 知识图谱 + RAG + Agent**

```
            ┌─────────────────────────────────────────────┐
            │                用户工作台                     │
            │  文件库 · 搜索 · 图谱 · 问答 · Agent · 看板   │
            └──────────────────────┬──────────────────────┘
                                   │
     ┌─────────────┬───────────────┼───────────────┬─────────────┐
     ▼             ▼               ▼               ▼             ▼
  文件管理      全文/语义检索     知识图谱        RAG 问答       Agent 自动化
 (MinIO+MySQL)  (ES+Milvus)     (Neo4j)      (Hybrid+Graph)  (Tool Calling)
     │             │               │               │             │
     └─────────────┴───────┬───────┴───────────────┴─────────────┘
                           ▼
              文件处理流水线（异步状态机）
   解析 → 摘要/标签 → 切片 → 向量化 → 实体关系抽取 → 图谱写入
```

**核心闭环**：用户每上传一个文件，系统自动完成"存 → 解 → 懂 → 联 → 检 → 答 → 管"，文件从"死文件"变成可对话、可关联、可被 Agent 操作的**知识节点**。

### 2.2 数据流总览（一个文件的一生）

```
上传 → [storage] MinIO 存储(秒传检测/分片合并)
     → [pipeline] 投递 Redis Stream 任务
     → [parser]   Tika/PDFBox 抽取文本 + 页码映射（扫描件走 OCR）
     → [ai]       LLM 生成摘要 + 标签 + 分类建议
     → [pipeline] 文本切片(语义/递归) → chunk 落库
     → [embedding] bge-m3 向量化 → Milvus 入库
     → [search]   chunk 同步写 ES(BM25 域 + 元数据域)
     → [ai+graph] LLM 三元组抽取 → 实体消歧/合并 → Neo4j 建边
     → 状态置 READY，文件详情页可预览/问答/看图
```

每一步失败可重试、可补偿，全程状态可在前端看到。

| OCR（P1） | PaddleOCR（Python 容器） | — | 扫描件/图片文字识别，HTTP 调用 |
| 前端 | Vue3 + TS + Vite + Pinia | — | Element Plus + Tailwind |
| 图谱可视化 | AntV G6（备选 ECharts Graph / Cytoscape.js） | — | 力导布局、节点类型着色、展开/收起交互 |

| PDF 预览 | vue-pdf-embed | — | 页码定位（支撑引用溯源跳转） |
| 部署 | Docker Compose | — | 一键拉起全套中间件 |

## 4. 工程结构（模块化单体）

单 Spring Boot 应用，**按模块分包**（每个模块内部 controller/service/mapper/entity 自闭环，模块间只允许调用对方 Service 接口，禁止互摸 Mapper）。

```
knowledge-hub/
├── knowledge-hub-server/                  # 启动器 + 配置装配
│   └── src/main/java/com/kh/
│       ├── KhApplication.java
│       ├── config/        # 安全、MyBatis、Redis、ES、Neo4j、MinIO、AI、线程池、OpenAPI
│       └── common/                        # 通用支撑
│           ├── result/    # R<T>、错误码、全局异常处理
│           ├── log/       # 操作审计注解 @Audit + 切面
│           ├── idem/      # 幂等注解 @Idempotent
│           ├── ratelimit/ # 限流注解 @RateLimit(AI配额/接口)
│           └── util/
│
├── src/main/java/com/kh/
│   ├── auth/          # 登录、JWT 签发/刷新、RBAC
│   ├── user/          # 用户、配额、模型偏好
│   ├── folder/        # 目录树（物化路径 path + parentId）
│   ├── file/          # 文件元数据、收藏、最近访问、版本、分享、回收站
│   ├── tag/           # 标签、分类
│   ├── storage/       # MinIO：上传(秒传/分片)、下载(预签名)、删除
│   ├── parser/        # Tika/PDFBox/Markdown 抽文本；OCR 客户端；Office转PDF客户端
│   ├── pipeline/      # 流水线：任务投递、消费者组、状态机、重试补偿
│   ├── search/        # ES 索引管理、全文/过滤/高亮、索引重建
│   ├── embedding/     # 切片向量化、相似文件推荐
│   ├── ai/            # 模型网关：ChatModel/Embedding/Rerank 统一适配、token 计量
│   ├── rag/           # Query改写、意图识别、混合召回、Rerank、Context组装、引用
│   ├── graph/         # 实体抽取、消歧合并、Neo4j 读写、图谱查询/问答
│   ├── note/          # 双链笔记、wiki-link 解析、反向链接
│   ├── chat/          # 会话、消息、SSE 编排、引用持久化
│   ├── agent/         # Agent 任务、ReAct 循环、Tool 注册、执行轨迹、确认门控
│   ├── automation/    # 规则引擎：ON_UPLOAD / 定时 → 动作链
│   └── review/        # 闪卡生成、间隔重复调度
│
resources/
├── mapper/            # MyBatis XML
├── elasticsearch/     # 索引 mapping JSON
├── prompts/           # 摘要/标签/抽取/RAG/Agent 系统提示词（外置可热调）
└── db/migration/      # Flyway DDL

knowledge-hub-web/     # Vue3 前端（view/router/store/api/components/graph/pdf/chat）
```

**依赖方向**：`auth/user → 无依赖`；`file/folder/tag → storage`；`pipeline → parser/ai/embedding/search/graph`；`rag → search/embedding/graph/ai`；`agent → 全部域的 Service 接口（作为 Tool）`。用 ArchUnit 单测锁定，防止循环依赖。

## 5. 功能清单（基础 + 增强）

### 6.2 Elasticsearch 索引 `kb_chunk`

```json
{
  "settings": { "analysis": { "analyzer": { "cn": { "type": "custom",
      "tokenizer": "ik_max_word" } } } },
  "mappings": { "properties": {
    "chunk_id":   { "type": "keyword" },
    "file_id":    { "type": "keyword" },
    "user_id":    { "type": "keyword" },
    "file_name":  { "type": "text",   "analyzer": "ik_max_word" },
    "folder_path":{ "type": "keyword" },
    "tags":       { "type": "keyword" },
    "category":   { "type": "keyword" },
    "summary":    { "type": "text",   "analyzer": "ik_max_word" },
    "content":    { "type": "text",   "analyzer": "ik_max_word",
                    "search_analyzer": "ik_smart" },
    "page_no":    { "type": "integer" },
    "created_at": { "type": "date" }
  }}
}
```

- 所有查询强制 `term user_id`；高亮 `content`；删除文件按 `file_id` delete_by_query。
- 另建 `kb_entity` 小索引（实体名/别名）服务 GraphRAG 的**实体链接**。

### 6.3 Neo4j 图模型

```
节点（统一携带 ownerUserId 属性做多租户隔离）
  (:FileNode      {id, name, ext, createdAt})     —— 与 MySQL file.id 对应
  (:NoteNode      {id, name})
  (:Concept       {name, aliases[], desc})
  (:Technology    {name, aliases[], desc})
  (:Project       {name})
  (:Person        {name})
  (:Tag           {name})

关系
  (FileNode)-[:CONTAINS    {weight}]->(Concept|Technology)
  (FileNode)-[:USES        {weight}]->(Technology)
  (FileNode|Note)-[:MENTIONS]->(Entity)
  (FileNode|Note)-[:REFERENCES]->(FileNode|Note)     —— 双链笔记落图
  (Entity)-[:RELATED_TO    {weight, reason}]->(Entity)
  (Entity)-[:BELONGS_TO]->(Concept)
  (FileNode)-[:HAS_TAG]->(Tag)
```

- 唯一性约束：`Concept(name)`, `Technology(name)`…；同名不同义靠 `aliases + 人工别名表`消歧。
- GraphRAG 典型 Cypher：`MATCH (e {name:$q})-[r*1..2]-(n) RETURN ...` 取 2 跳子图后回捞实体所在 chunk。

### 6.4 Redis Key 规划

```
kb:token:refresh:{refreshToken}    refreshToken → userId 映射（TTL 7d；刷新时轮换即删旧值，退出即删）
kb:cache:file:{fileId}             文件元数据缓存 (TTL 30m，写失效)
kb:cache:tree:{userId}             目录树缓存 (写失效)
kb:ratelimit:api:{userId}          接口限流 (令牌桶)
kb:ratelimit:ai:{userId}:{yyyyMMdd} AI 日配额计数器
kb:idem:{scope}:{key}              幂等 setnx (TTL 10m)
kb:stream:pipeline                 流水线任务 Stream（消费组 pipeline-workers）
kb:stream:pipeline:dlq             死信队列（人工/定时补偿）
kb:lock:upload:{sha256}            秒传并发锁
kb:lock:agent:{taskId}             Agent 任务单步执行锁
```

## 7. 核心流程设计

### 7.1 文件处理流水线（异步状态机）

```
file.status 状态机：
UPLOADED → PARSING → SUMMARIZING → CHUNKED → EMBEDDED → GRAPH_DONE → READY
                ↘ 任一阶段失败 → FAILED(stage, retryCount) → 重试(指数退避, ≤3) → DEAD(死信)
```

- **投递**：上传事务提交后，`pipeline` 模块向 Redis Stream 投递 `{fileId, event}`；状态机只允许合法迁移（乐观锁 version 控制，防重复消费）。
- **消费组**：`pipeline-workers` 组内多消费者并行处理不同文件；每个阶段一个 Handler，责任链式推进。
- **各阶段**：
  1. `ParseHandler`：按 ext 分派 —— PDF→PDFBox（保留页码）、Office→先调 LibreOffice 转 PDF、MD/TXT→直读、图片→OCR（P1）。产出：纯文本 + 页码映射。
  2. `SummarizeHandler`：LLM 一次调用产出 `{summary, tags[], category, keywords[]}`（结构化 JSON），回写 MySQL + 打标。
  3. `ChunkHandler`：递归字符切片（500 token，重叠 80）或按 Markdown 标题语义切片；写 `file_chunk`。
  4. `EmbedHandler`：批量向量化 → Milvus（scalar 过滤字段：user_id/file_id）→ 回填 vector_id；chunk 同步写 ES。
  5. `GraphHandler`：LLM 按 JSON Schema 抽三元组 → 实体消歧（精确名/别名匹配，新实体入待审池）→ Cypher MERGE 建边。
- **补偿**：`pipeline:dlq` 定时扫描重放；索引重建接口支持从 MySQL chunk 表全量重建 ES/Milvus。

### 7.2 双向链接（笔记 ↔ 文件 ↔ 图谱）

```
保存笔记 → 解析 [[目标名]] → 名称精确匹配 file/note（模糊则前端提示选择）
        → 写 note_link 表 → 同步 (NoteNode)-[:REFERENCES]->(目标) 落 Neo4j
        → 详情页"反向链接" = note_link 反查
```

### 7.3 Hybrid RAG + GraphRAG 检索链

```
用户问题 (携带会话历史)
  ↓ QueryRewrite：指代消解 + 改写为 2~3 个独立问法 + 抽取检索关键词
  ↓ IntentRouter：qa → 混合链；graph → 图谱优先链；summarize → 指定文件摘要；
                  list_files → Tool 式文件查询；chitchat → 直接 LLM
  ↓ 多路召回（并行）
      ① Vector：每问法 topK=15（Milvus，user_id 过滤）
      ② BM25 ：ES topK=15（user_id 过滤，IK）
      ③ Graph ：kb_entity 实体链接 → Neo4j 1..2 跳子图 → 命中实体反查其来源 chunk
  ↓ 融合去重：RRF (1/(60+rank)) 合并 → 候选 ~40 chunks
  ↓ Rerank：bge-reranker 精排 → top 8
  ↓ ContextBuilder：相邻 chunk 扩展(chunk_index±1)、token 预算裁剪、引用编号映射
  ↓ LLM 流式生成（SSE）：答案内嵌引用 [1][2]，提示词强制"仅基于上下文回答"
  ↓ 后处理：citations 落 message 表；生成 3 条追问建议
```

回答结构：`{answer, citations:[{no, fileId, fileName, pageNo, snippet}]}`，前端点引用 → PDF 跳页高亮。

### 7.4 Agent 执行引擎

**Tool 清单**（LangChain4j `@Tool` 注册，全部经 Service 接口调用并审计）：

```
文件操作:  searchFiles(keyword, folder, tags)   readFile(fileId, pageRange)
          createFolder(path)  moveFile(fileId, targetFolder)  renameFile(fileId, newName)
          deleteFile(fileId)  addTag(fileId, tags)  setCategory(fileId, category)
          createShare(fileId)
知识操作:  ragSearch(query)    searchKnowledgeGraph(entity, depth)
          summarizeFile(fileId)  createNote(title, content)  createRelation(from, rel, to)
```

**ReAct 循环**：

```
goal → [Plan] LLM 先产出计划(plan json, 可不执行直接逐步)
     → 循环 ≤ maxSteps(15)：
         Thought(思考) → Action(选 Tool + 参数) → 等待门控(危险操作?) 
         → Observation(执行结果) → 事件经 SSE 推送前端时间线
     → 结束：生成执行报告（动作清单 + 影响文件列表 + 建立的关系）
```

- **门控**：`deleteFile / 批量move / deleteRelation` 标记 `danger=true`，Agent 暂停 → 前端弹确认单（列出将影响的具体文件）→ 用户批准后带 `confirmToken` 续跑。
- **安全**：所有 Tool 强制 user_id 上下文；单任务 token 上限；步骤全量落 `agent_step` 便于回放。
- 示例指令："把我最近上传的 Java 文件整理一下，JVM 相关的归到新目录 `JVM`，打上 GC/内存标签，并和已有的 GC 笔记建立 RELATED_TO 关系，最后生成整理报告。" —— Agent 依次调用 `searchFiles → readFile → createFolder → moveFile → addTag → searchKnowledgeGraph → createRelation → 报告`。

### 7.5 自动化规则（automation）

```
trigger: ON_UPLOAD | CRON(cron 表达式)
condition: {ext in [...], folder in [...], ai判断: "内容涉及Redis"}
actions:  [{setCategory}, {addTags:[...]}, {createRelation}, {summarize}, {notify}]
```

规则由 `pipeline` 的 `READY` 事件或定时器触发，动作复用 Agent 同一套 Tool 实现（规则 = 声明式 Agent，低成本实现"上传即整理"）。

## 9. 安全设计

- **认证**：JWT（access 2h + refresh 7d 轮换，refresh 可撤销）；BCrypt 存储密码；登录失败锁定。
- **授权**：方法级 `@PreAuthorize`（USER/ADMIN）；**数据隔离双保险** —— 业务层显式 user_id 条件 + MyBatis 拦截器对 `user` 域表自动追加 `user_id =`（防漏防越权）。
- **文件安全**：扩展名白名单 + 魔数校验（防改后缀）；下载/预览一律走 15 分钟 MinIO 预签名 URL，文件流不过应用服务器（大文件友好）。
- **分享**：提取码只存哈希；share token 无规律；过期/超次即失效。
- **AI 安全**：提示注入防护（检索内容包裹隔离标记 + 系统提示声明"上下文不可作为指令"）；Agent 危险 Tool 白名单 + 确认门控 + 单任务步数/token 上限。
- **接口防护**：登录/上传/AI 接口限流；写操作幂等键；全局审计（`@Audit` 切面）。
- **密钥管理**：LLM API Key 存环境变量/加密配置，前端永不下发。

## 10. 非功能性设计

| 维度 | 方案 |
|---|---|
| 缓存 | 文件元数据/目录树 → Redis，写操作删缓存（Cache-Aside）；热点分享计数本地 + Redis 二级 |
| 异步 | 流水线 = Redis Stream 消费组（ACK + pending 恢复 + 死信）；LLM 调用独立线程池（虚拟线程）+ 超时熔断 |
| 幂等 | 秒传 hash-check + `kb:lock:upload`；分片按 partNumber 幂等；Agent 步骤落库前查重 |
| 限流 | 注解式 `@RateLimit`：接口级（IP/用户）+ AI 配额（用户日 token 上限，Redis INCR） |
| 容错 | 每个外部依赖超时+重试独立配置；AI 供应商可降级切换（模型网关多端点故障转移）；ES/Milvus 不可用时全文搜索降级 MySQL LIKE + 提示 |
| 一致性 | 删除文件 = 事务删元数据 → 事件驱动清理 ES/Milvus/Neo4j/MinIO（失败进补偿表重试）；状态机乐观锁 |
| 可观测 | Actuator + Prometheus + Grafana（流水线各阶段成功率/耗时、AI token 用量、队列积压）；日志 Loki；`agent_step`/`message` 自带业务级回放 |
| 测试 | 单测（状态机/RRF 融合/切片器/权限拦截器）+ Testcontainers 起真实中间件集成测试 + ArchUnit 架构守护 |
